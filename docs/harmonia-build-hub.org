#+TITLE: silver as the build hub and LAN binary cache — implementation plan
#+DATE: 2026-10-23
#+OPTIONS: toc:t
#+STARTUP: overview

* Goal

Make builds reproducible and cheap across the four machines:

- =silver= is the single place where build outputs are collected, rooted, and
  served as a signed Nix binary cache (Harmonia).
- =mist= (aarch64-darwin), =misfit= (x86_64-linux) and =dgx-spark=
  (aarch64-linux) are the only machines that compile.
- A trigger (manual / timer / CI) submits closures; Nix's distributed-build
  scheduler acts as the job queue; outputs land in silver's =/nix/store=.
- Every host, including the macs, substitutes from silver when it is on the
  LAN, so a deploy of an already-built closure is mostly a copy.

This document is the build-hub counterpart to =docs/harmonia-silver.org=
(branch =feat/harmonia-silver=), which only plans a read-only cache of whatever
silver happened to build for itself. Phase 1 below reuses that module; the
difference is that silver now accumulates aarch64 and darwin paths too, so
the "x86_64-only cache" limitation in that draft no longer applies.

* TL;DR — shortest path

1. *Phase 0:* prove Harmonia runs on silver and that silver can ssh-ng into
   mist, misfit and dgx-spark; one tiny =hello= per builder. Stop if Lix on
   mist does not speak the Nix 2.34 remote protocol.
2. *Phase 1:* Harmonia on silver with a =silver-1= signing key and roots.
3. *Phase 2:* add =http://silver.lan:5000= + key to
   =modules/nix-custom-conf.nix= (guarded; LAN hosts only).
4. *Phase 3.1–3.4:* builder key, =nix.buildMachines= on silver, and
   =just cache-build= from the Mac: evaluate there, copy the drv closure to
   silver, let silver realise it with =--max-jobs 0=. Outputs land on silver
   and the macs can substitute them.
5. *Phase 3.5:* only after step 4 works, move evaluation to silver with a
   systemd timer (needs a repo checkout + the private input on silver).
6. *Phase 4–5:* keep colmena =buildOnTarget = true=, run =just cache-build=
   after deploys, and let Harmonia GC/roots handle retention.

Do not enable the timer or change colmena's build location in the same change
as Phase 1; those are the two places that turn a cache problem into a deploy
outage.

* Non-goals

- Replacing cache.nixos.org or the public caches. Silver is an *additional*
  substituter, priority below the public ones, useful for our own drvs and
  pinned-nixpkgs rebuilds.
- A web UI, job history, or PR gating. That is Hydra; see "Alternatives".
- Cross-architecture *emulation*. Every drv is built on a native builder.
- Serving the cache outside the LAN/tailnet. Harmonia has no auth and can
  serve any path in silver's store, including the private flake input source.

|------------+-----------------+------------------------+----------+-------|

Facts that shape the plan:

- silver is reachable as =silver.lan= (router DNS) and =silver.local= (mDNS);
  the draft's note about a duplicate =silver= on the LAN did not reproduce
  today, but use =silver.lan= in config.
- silver has *no* SSH access to any builder today: =ssh yuanw@silver.lan
  'ssh yuanw@dgx-spark'= => Permission denied. Phase 3 creates that key.
- silver has no tailscale, so =http://silver.lan:5000= is a LAN-only
  substituter. A traveling host (asche, sometimes mist) must either be
  excluded or pay =connect-timeout= on every miss.
- The private flake input is =git+https://github.com/yuanw/nix-home-private=
  and is currently fetched with the deploying user's credentials, or copied
  as a store path by colmena. A silver-side evaluator does not have those
  credentials yet (Phase 3.5).
- Existing cache settings live in =modules/nix-custom-conf.nix= and are
  =mkForce='d, so the cache consumer change is one file for both NixOS and
  nix-darwin.
- =nix.gc= is already weekly on silver, misfit, dgx-spark. Do not run it
  alongside Harmonia's GC.
- =nixpkgs#harmonia= is 3.3.0 at this pin; its NixOS module has
  =cache.signKeyPaths=, =cache.settings=, and =gc.gcRootsDirs=. No push API.

* Architecture

#+begin_example
                 trigger (just / timer / CI)
                              |
                              v
  mist (aarch64-darwin) <- silver: eval + Nix scheduler + store <- Harmonia :5000
  misfit (x86_64-linux) <-   |         copies outputs back        |
  dgx-spark (aarch64-linux) <-          and roots them           v
                                                          consumers:
                                                          silver, misfit,
                                                          dgx-spark, mist, ...
#+end_example

Two possible triggers, same execution path:

- *Variant A — Mac-triggered (recommended first).* The Mac evaluates the
  flake (it has the private input), copies the derivation closure to silver,
  and silver realises it with =--max-jobs 0=, dispatching to the builders.
  No new credentials on silver; works today.
- *Variant B — silver-triggered (autonomous, Phase 3.5).* A systemd timer on
  silver does the fetch/build itself. Requires the private input and a repo
  checkout on silver.

Both end with the same thing: outputs in silver's store, a gcroot per closure,
and Harmonia signing narinfo for them.

* Decisions to make before Phase 1

| # | Decision | Recommendation |
|---+----------+----------------|
| D1 | Trigger | Variant A first (=just cache-build=); add the timer only after it works |
| D2 | Reachability | LAN only for now; if mist/asche travel a lot, put tailscale on silver and use the tailnet name in Phase 2 |
| D3 | Retention | 30d / =ensureFree = "50G"=; silver has 423G free and the store is 11G today |
| D4 | Cache key name | =silver-1=; bake it into the secret and never rename (clients pin it) |
| D5 | Which closures | =packages.silver=, =packages.misfit=, =packages.dgx-spark=, =packages.mist=; add =asche= / =ci= later |
| D6 | x86_64 fallback | =max-jobs = 0= on silver at first (misfit only); set 2 if misfit downtime hurts |

* Phase 1 — Harmonia on silver (~1 hour, one deploy)

** 1.1 Signing key (operator only)

#+begin_src bash
umask 077
nix key generate-secret --key-name silver-1 > ~/silver-1.secret
nix key convert-secret-to-pub < ~/silver-1.secret
# → silver-1:<base64>   (this is the public key that goes to consumers)
shred -u ~/silver-1.secret
#+end_src

Keep a copy of the secret in the password manager. If it is lost, every
consumer's =trusted-public-keys= entry must be rotated.

** 1.2 agenix secret

In =secrets/secrets.nix=:

#+begin_src nix
"harmonia-sign-key.age".publicKeys = [ silver ];
"nix-builder-key.age".publicKeys = [ silver ];   # Phase 3
#+end_src

#+begin_src bash
agenix -e secrets/harmonia-sign-key.age < ~/silver-1.secret
git add secrets/harmonia-sign-key.age secrets/secrets.nix
#+end_src

The Harmonia module passes the key to the unit with =LoadCredential=, so it
must be root-readable (=mode = "0400"=), not owned by a static service user.

** 1.3 Module =modules/services/cache/harmonia.nix=

#+begin_src nix
{ config, lib, ... }:
let
  cfg = config.services.harmonia-cache;
  port = 5000;
in
{
  options.services.harmonia-cache = {
    enable = lib.mkEnableOption "LAN Nix binary cache served from this host's /nix/store";
  };

  config = lib.mkIf cfg.enable {
    age.secrets.harmonia-sign-key = {
      file = ../../../secrets/harmonia-sign-key.age;
      mode = "0400";
    };

    services.harmonia = {
      cache = {
        enable = true;
        signKeyPaths = [ config.age.secrets.harmonia-sign-key.path ];
        settings = {
          bind = "[::]:${toString port}";
          # Below cache.nixos.org's 40 so the LAN wins when both have the path.
          priority = 10;
        };
      };
      # Replaces nix.gc on this host; nixpkgs warns if both are automatic.
      gc = {
        enable = true;
        automatic = true;
        dates = [ "weekly" ];
        deleteOlderThan = "30d";
        ensureFree = "50G";
        keepRecent = "1d";
        # Phase 3 puts one indirect root per closure here.
        gcRootsDirs = [ "/nix/var/nix/gcroots/cache" ];
      };
    };

    networking.firewall.allowedTCPPorts = [ port ];

    # The cache has nothing to serve that GC already collected.
    nix.settings = {
      keep-derivations = true;
      keep-outputs = true;
    };
  };
}
#+end_src

* Phase 2 — make consumers use it (~30 min, no builds)

** 2.1 Add the substituter and key

=modules/nix-custom-conf.nix= is common to NixOS and nix-darwin. Put silver in
the =let= lists, not only in =nix.settings=, because those lists are also
rendered into =/etc/nix/nix.custom.conf= for the Lix/Determinate hosts (mist):

#+begin_src nix
let
  # silver has no tailscale; LAN only. Keep traveling hosts out until/unless
  # silver joins the tailnet (D2).
  useSilver = config.my.hostname != "asche";
  silverUrl = "http://silver.lan:5000";
  silverKey = "silver-1:<base64>";
  cacheSubstituters = lib.optionals useSilver [ silverUrl ] ++ [
    # ... the existing list, unchanged ...
  ];
  trustedPublicKeys = lib.optionals useSilver [ silverKey ] ++ [
    # ... the existing list, unchanged ...
  ];
  trustedSubstituters = cacheSubstituters;
in
{
  nix.settings = {
    substituters = lib.mkForce cacheSubstituters;
    trusted-substituters = lib.mkForce trustedSubstituters;
    trusted-public-keys = lib.mkForce trustedPublicKeys;
    # A powered-off silver must not stall every missing path for a minute.
    connect-timeout = 5;
  };
}
#+end_src

The existing =environment.etc."nix/nix.custom.conf"= block already renders
=trusted-users=, =substituters=, =trusted-substituters= and
=trusted-public-keys= from these lets, so mist gets silver automatically.

** 2.2 Verify substitution

Pick a path that is on silver but not on the consumer (build one with a
different output on silver first, e.g. the Phase 0 probe), then:

** 3.4 Variant A: trigger from the Mac

Add to =justfile=:

#+begin_src make
# Build every host closure on silver's builders and root it there.
# The Mac evaluates (it has the private flake input); silver only schedules.
cache-targets := "silver misfit dgx-spark mist"

cache-build:
    @set -e; \
    for t in {{cache-targets}}; do \
      echo "== $t"; \
      drv=$({{nix}} eval --raw ".#packages.$t.drvPath"); \
      {{nix}} copy --derivation --to ssh-ng://yuanw@silver.lan "$$drv"; \
      ssh yuanw@silver.lan "nix-store --realise '$$drv' \
        --max-jobs 0 --keep-going \
        --add-root /nix/var/nix/gcroots/cache/$t --indirect"; \
    done
#+end_src

Why =nix-store --realise= rather than =nix build=: we already measured that
=nix build <drv)= on the Spark exits 0 without building when handed a .drv
path; =nix-store -r= is the reliable remote-store form.

Run it once with one target first:

#+begin_src bash
just cache-build   # four targets; start with packages.misfit if you want a
                   # smaller first run
#+end_src

The loop is deliberately serial: each target closure is one system, so it
only occupies one builder. Once the serial version is proven, a
=--parallel= mode that backgrounds the four =nix-store --realise= calls and
waits is the way to keep all three builders busy; do not start there.

Expected: silver dispatches each missing drv to the matching builder, copies
outputs back, and leaves a root per target:

#+begin_src bash
ssh yuanw@silver.lan 'ls -l /nix/var/nix/gcroots/cache/'
ssh yuanw@silver.lan 'nix-store --query --roots /nix/store/<system-path>'
#+end_src

** 3.5 Variant B: make silver self-triggering (optional, after A works)

Prerequisites:

1. A checkout of the public repo on silver:
   =git clone https://github.com/yuanw/nix-home /var/lib/nix-home=.
2. The private input available at evaluation time. Pick one:
   - *Preferred:* a read-only deploy key for =nix-home-private= on silver,
     checked out at =/var/lib/nix-home-private=, and pass
     =--override-input nix-home-private path:/var/lib/nix-home-private=.
     This is explicit, testable, and needs no daemon credential magic.
   - Or =nix flake archive --to ssh-ng://silver= from the Mac after each lock
     update; the store already contains the private source, but verify that
     evaluation does not refetch.
   - Not recommended: a GitHub token in the daemon's config. The input is
     =git+https=, and the current comment in =flake.nix= records why the
     client-side credential helper was chosen.

Then a systemd service + timer on silver (same targets and roots as 3.4):

#+begin_src nix
systemd.services.nix-cache-build = {
  description = "Build nix-home closures on the LAN builders";
  # serialise with deploys; the service itself is oneshot
  serviceConfig = {
    Type = "oneshot";
    Nice = 10;
    ExecStart = "/etc/nix-cache-build.sh";
  };
};

systemd.timers.nix-cache-build = {
  wantedBy = [ "timers.target" ];
  timerConfig = {
    OnCalendar = "hourly";     # or "*-*-* 04:15"
    Persistent = true;
    RandomizedDelaySec = "10min";
  };
};
#+end_src

The script is 3.4's loop plus:

#+begin_src bash
git -C /var/lib/nix-home fetch --prune origin
git -C /var/lib/nix-home reset --hard origin/main
cd /var/lib/nix-home
# same nix-store --realise loop, with --override-input on the private path
#+end_src

Do not run the timer until Variant A has produced a successful first cache
generation; debugging eval + builders + GC at once is how this becomes a
weekend.

* Phase 4 — make deploys use the cache (~30 min)

Nothing has to change in colmena yet:

- Hosts have =buildOnTarget = true=, so they still build their own closure,
  but silver is now a substituter and holds the same drv hashes. The target
  fetches instead of compiling. This is the low-risk end state.
- After a deploy, run =just cache-build= to warm the cache for the other
  hosts and the next rebuild. A failed target only fails that target
  (=--keep-going=) and does not block the deploy.
- If you later want silver to be the deploy builder too, run colmena *on
  silver* with =--no-build-on-target=; silver has the builders and the store.
  That is a separate change; do not couple it to this one.

Add two read-only recipes:

#+begin_src make
# what is rooted and how big is the store
cache-status:
    @ssh yuanw@silver.lan 'ls -lh /nix/var/nix/gcroots/cache; df -h /; du -sh /nix/store'

# one host at a time (same loop as cache-build, parameterised)
cache-build-one HOST:
    @drv=$({{nix}} eval --raw ".#packages.{{HOST}}.drvPath"); \
     {{nix}} copy --derivation --to ssh-ng://yuanw@silver.lan "$$drv"; \
     ssh yuanw@silver.lan "nix-store --realise '$$drv' --max-jobs 0 --keep-going \
       --add-root /nix/var/nix/gcroots/cache/{{HOST}} --indirect"
#+end_src

* Phase 5 — operations and failure modes

** GC and roots

- One root per host closure, replaced on every successful build.
- Harmonia GC =ensureFree = "50G"= is the backstop; =keep-outputs= grows the
  store between GCs.
- If a target is dropped from =cache-targets=, delete its root; otherwise the
  closure stays forever.
- Never enable both =nix.gc.automatic= and =services.harmonia.gc.automatic=.

** Availability

- mist sleeps: darwin builds fail or wait. If that becomes annoying, either
  add a second darwin builder (=ci=?) or accept that mist is opportunistic.
- dgx-spark runs inference: =maxJobs = 1=, and do not schedule a CUDA source
  build there while a model is resident. The 2026-10-23 CUDA 13.4 experiment
  showed a build can also fail on ptxas; =--keep-going= keeps it from taking
  the rest of the cache down.
- If silver is off, consumers pay =connect-timeout = 5= per miss and fall
  through. Do not list silver on hosts that are usually off-LAN (D2).

** Security

- Harmonia is unauthenticated and serves any path in silver's store,
  including =nix-home-private= source and any pinned proprietary source.
  LAN/tailnet only; never expose it on =*.yuanw.me=.
- The cache signing key is the cache's identity. Losing it means rotating
  =trusted-public-keys= everywhere; back it up.
- The builder key can run builds on all three machines. Root-readable 0400,
  one key, revoke by removing the authorized_keys entry.

** Upgrades**

- Harmonia comes from the repo's nixpkgs; bump it with the rest of the flake.
  Its socket unit is derived from =settings.bind=, so the firewall port and
  =bind= must stay in sync.
- After changing =nix.buildMachines=, deploy silver and check =/etc/nix/machines=
  before the next trigger.

* Phase 6 — rollback

1. Disable =services.harmonia-cache.enable= on silver (service, secret mount,
   firewall port, and GC module all go away with =mkIf=).
2. Remove the silver substituter/key from =modules/nix-custom-conf.nix=.
3. Remove =nix.buildMachines= / =nix.distributedBuilds= from silver.
4. The store paths and roots can stay; they are harmless. Remove
   =/nix/var/nix/gcroots/cache/*= and let the next GC collect them.
5. The =nix-builder-key.age= and =harmonia-sign-key.age= secrets can stay;
   re-enabling later does not need new keys.

* Alternatives considered

** Hydra on silver

Hydra gives a persistent queue, eval history, a UI, per-jobset gating, and its
own binary cache; it also knows how to use =buildMachines=. It costs
Postgres + the Hydra web service + a jobset definition, and it is a much
larger attack surface on a LAN-only box. Adopt it only if you want PR checks
or "which build failed and why" history. For four hosts and a home LAN, the
Nix scheduler + a timer is enough.

** attic instead of Harmonia

atticd is a push cache: builders run =attic push= and atticd handles chunking,
deduplication, and GC. That removes the need for silver to be a build client,
but adds a client on every builder and a database/storage service on silver.
Harmonia + Nix distributed builds is fewer moving parts *because* silver is
already the collection point.

** GitHub Actions self-hosted runner on silver

Gives a queue and logs, but this repo is public: a self-hosted runner that
executes fork PRs is a remote-code-execution hole. Only with a private repo or
a workflow that never checks out untrusted refs.
