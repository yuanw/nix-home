* What this is

The exit gate for "Phase 0 — prove the pieces" in [[file:harmonia-build-hub.org][harmonia-build-hub.org]], run
from =mist= on 2026-10-23. No repo file was changed and no host was deployed; the
only mutations were a throwaway =authorized_keys= on mist (removed again) and

* Findings that change later phases

** 1. silver reaches builders only via a forwarded agent (blocks Phase 3 as written)

=ssh yuanw@silver 'ssh yuan@misfit'= fails on its own; it worked only with
=ssh -A= from mist. So =nix.buildMachines= with =sshKey =
config.age.secrets.nix-builder-key.path= (3.1) is still required — nothing
about 0.2's PASS removes that. 0.2 proves the *builders accept this key and
this user*, not that silver holds a key.

** 2. mist has no =~/.ssh/authorized_keys= at all

=ssh yuan@mist.lan= is =Permission denied (publickey)= from any machine,
including mist itself: =/Users/yuan/.ssh/authorized_keys= does not exist even
though =hosts/mist.nix:74= declares the phone key. For this probe only I wrote
=ssh-add -L= to that file and =rm='d it afterwards. Phase 3.1 must actually
land a key there and *verify the file after darwin-rebuild* — otherwise mist
is not a builder at all and the darwin closures never reach silver.

** 3. =modules/nix-custom-conf.nix= does not reach misfit or dgx-spark (Phase 2)

Only =yuan-mac=, =mist=, =asche= and =wk01174= import =myModules.common=.
Live =/etc/nix/nix.conf=:

| Host | substituters today |
|------------------------------------+--------------------------------------------------------------------|
| mist | from =/etc/nix/nix.custom.conf= (the mkForce'd list) — gets it |
| misfit | =https://cache.nixos.org/= only |
| dgx-spark | its own list: nix-community, cuda-maintainers, nixos-cuda, graham33, ai, ... + flox via extra- |
| silver | =https://cache.nixos.org/= only |

So Phase 2's "one file for both NixOS and nix-darwin" is true only for the
=myModules.common= hosts. =misfit= has no =nix.settings= block at all and
=dgx-spark= has one at =hosts/dgx-spark/configuration.nix:82= — add the silver
substituter + key there too, or import a small cache-consumer module in both
host trees. Keeping the guard and the key together still matters (=require-sigs=).

** 4. dgx-spark probes a cachix it cannot read

Every miss pays =HTTP error 401= from =https://cuda-maintainers.cachix.org/nix-cache-info=
("Binary cache cuda-maintainers doesn't exist or you're not authorized").
Pre-existing, unrelated to harmonia, but it is noise on every build and one more
round trip per path; drop it or give it a token while touching that block.
